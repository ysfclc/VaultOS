# VaultOS risk register

_Last reviewed: 2026-11-25. Severity reflects user/data impact, not implementation effort._

| ID | Risk | Likelihood | Impact | Severity | Mitigation / next action | Owner / state |
|---|---|---|---|---|---|---|
| RISK-001 | Physical acceptance on Redmi Note 12 Pro 5G has not been recorded; keyboard ergonomics, permission behavior, Xiaomi background work, accessibility and performance may differ from CI. | Unknown | High | High | Execute docs/DEVICE-TEST-PLAN.md on the actual device, record OS/API/MIUI version and observed results. Do not call 1.0.0 device-verified beforehand. | User/device operator — open |
| RISK-002 | Historical signing keystore is tracked in a public repository and Gradle signing configuration contains static credentials. The signing identity and credentials must be treated as exposed; an attacker could sign an update under the same identity. | High | Critical | Critical | Make the repository private as temporary containment (not history remediation); provision a replacement key outside Git, generate/validate API 28+ v3 signing lineage, test in-place updates and app-data preservation, then remove the old key and rewrite history only after retaining the lineage securely. Gradle no longer references the exposed key; test APKs use the generated debug signer, release remains unsigned and new Vercel APK publication is paused. The live production alias still serves the previous 0.13.0 APK/ZIP links until the verified pause page is promoted. | User + maintainer — GOV-001 blocked |
| RISK-003 | SAF backups are not encrypted by VaultOS. Anyone with access to the chosen provider/drive may read the copied payloads and manifest. | Medium | High | High | Keep destinations access-controlled and explain the plaintext backup boundary before use. Encryption requires a separately specified key lifecycle and recovery design. | Product — accepted limitation |
| RISK-004 | Backup/restore still lacks automated end-to-end round-trip and malformed/corrupt archive coverage. Unsafe recycle-bin manifest paths could otherwise be persisted outside the private vault. | Medium | Critical | High | Partial mitigation: canonical vault-relative resolver now rejects absolute/traversal/drive-prefixed paths and symlink escapes for restored archive and recycle-bin paths, with JVM regression tests. Continue with v1/v2 fixture round-trips, checksum/corruption cases and atomic rollback behavior. | Engineering — in progress |
| RISK-005 | Room migrations and relationships have no identified migration regression tests. A schema change could strand existing catalogue data. | Medium | High | High | Add migration tests for supported schema versions and assert row/foreign-key/cascade preservation before changing schema. | Engineering — open |
| RISK-006 | Automatic clipboard capture is privacy-sensitive and works only when VaultOS is the selected IME. Source apps may omit the sensitive-clip flag. | Medium | High | High | Keep capture optional/clearly disclosed, preserve password-field checks, provide immediate disable/switch controls, and run the app-by-app device matrix using synthetic content only. | Product/device operator — open |
| RISK-007 | Broad shared-storage access is required for device-wide file management and indexing; Android still restricts app-private and some protected directories. | Medium | High | High | Request permission contextually, explain scope, handle denial/revocation, and never imply access to other apps' private sandboxes. Validate Android 13–15 behavior. | Product/device operator — open |
| RISK-008 | Android/MIUI/HyperOS may defer WorkManager and observer-triggered scans; no exact catch-up time can be promised. | High | Medium | Medium | Keep event-driven requests plus periodic catch-up; measure behavior on the target phone under default and relaxed battery policies; state the limitation clearly. | Engineering/device operator — open |
| RISK-009 | Current JVM tests cover pure classification, file operations, metadata parsing and suggestion ranking, but not key persistence/integration paths (scan, Room, archive repository, clipboard, backup, provider, UI). | High | High | High | Expand tests in small vertical slices. Prioritize backup/restore and Room migrations before further feature expansion. | Engineering — open |
| RISK-010 | Build instructions depend on a machine-installed Gradle 8.9; no Gradle wrapper is checked in. Builds may be less reproducible outside hosted Actions. | Medium | Medium | Medium | Document the exact toolchain and consider a wrapper with a pinned distribution/checksum in a separate low-risk increment. | Engineering — backlog |
